## 改动

- 每家公司保存有限`pending_batch`，包含冻结的规范化申报元数据、日期提交边界、同日收盘清单和完成子集。首次正文请求之前保存队列；最后一份成功时在同一次checkpoint提交基线并清队列。
- 取消、元数据暂不可达或扫描窗口变化不再替换当前批次。新的份数限制从下一批生效；关闭关注会暂停，改变筛选需恢复原条件或明确重置。显式下载单份历史申报不修改自动队列。
- 元数据失败不再冒充“没有新文件”。保存失败与用户取消分别报告；保留已发布原文，回滚到最后确认的内存状态，后续重试校验复用成品。
- 设置保存采用深拷贝，失败时恢复旧payload；不会把邮箱、Key或旧`sec_watchlist`兼容段写入队列。
- 菜单新增需明确确认、一次性消费、忙碌时拒绝的“重置下载记录”。只重置下载状态，不删除书、阅读记录或其他偏好；重置失败恢复旧内存记录。
- 阶段日志记录batch/filing/metrics/fetch/clean/images/publish和现有GC之后的Lua堆、RSS/HWM、字节数。采样工具独立读取生产PID，使用单调时钟限制时长，支持stop文件，PID身份变化时停止；不调用电源接口，不得用于休眠期间轮询。

0.2.4及更旧版本不会保留新队列字段，不能把未完成批次直接降级后仍称为稳定重试。回滚代码不等于可以覆盖随后新增的书籍、阅读状态或凭据；数据恢复须另行明确范围。

队列有结构一致性检查及Adler-32校验，用于检测意外截断或字段变化；**这不是针对有设置编辑权限者的防篡改认证，也不是fsync或跨进程事务保证**。损坏/未知版本队列保留并拒绝执行，不静默重选。旧进度有seen却无基线时要求明确重置，不擅自猜测历史目标。
