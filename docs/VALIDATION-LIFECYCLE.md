## 用户问题与实现范围

用户主动删除了 SEC EPUB，希望插件不再留下无用的附属资料。2026-10-08 的只读生产检查发现五份快照/翻译状态，以及八个旧侧车目录。这是当时的状态，不保证仍与后续设备操作一致。

本次实现：

1. **只读检查与确认后清理分离。** `sec_lifecycle.lua` 提供 `scan()`、`preview(ids, opts)`、`execute(plan)`；打开菜单不会删除文件。
2. **整份删除与残留清理分离。** 整份删除核对成品归属哈希；残留清理遇到仍存在的原文或中文版会停止。阅读记录需明确纳入清理范围。
3. **缺失不是删除证明。** 本地列表显示“文件位置待核对”；带同一登记号的移动/别名文件会阻塞清理。完全改名或移出受管范围需用户确认不再需要原位置附属资料。
4. **按申报归属翻译缓存。** 新缓存保存在 `<work>/<CIK>/<accession>/translation-cache/`。旧共享缓存预检只读，实际翻译时可复制有效命中，不因迁移重新请求模型。
5. **全局缓存独立管理。** 单份删除不清空旧共享缓存或公司搜索索引。共享翻译缓存清空前单独提示再次翻译可能收费。
6. **中断后重新确认。** 有界 JSON 记录通过临时文件原子提交，位于工作根的 `.cleanup-<CIK>-<accession>.json`。源记录删除后，仅允许用户重新确认空目录收尾；日志不是删除新增文件的授权。
7. **历史侧车有限识别。** 识别默认七家公司旧合集命名的 `.sdr` / `.epub.sdr`。只处理已确认目标的已知本地元数据、封面和插件进度文件；未知文件或目录保留。

### 明确保留的内容

- 仍在使用的原文、中文版及共同资料；
- 未明确选择删除的本地阅读记录；
- Key、设置、关注列表、增量下载基线；
- 其他申报的专属缓存、未单独确认的旧共享缓存和公司索引；
- 全局阅读历史、收藏、集中存储/hash 元数据；
- 未知/损坏资料、无法确定归属的文件、未完成发布文件；
- 启动器、备份、其他插件及系统文件。

## 生命周期覆盖

- 原文尚存、仅译文尚存、两份都缺失及完整成品的显式删除；
- 预览无副作用，失效或重复确认不继续执行；
- 文件重现、确认后新增文件、源文件变化、任务开始后拒绝清理；
- 公司别名/移动候选、未完成发布、损坏状态和结构错误的素材 JSON；
- 符号链接、硬链接、丢失根目录、扫描期间新增公司/申报目录；
- 未知普通文件、未知空目录、登记图片被替换、成品被替换；
- 本地侧车保留与明确纳入删除、旧侧车不会影响新版成品；
- 删除失败、source 删除后的目录失败、重启收尾、部分日志写入及重试；
- 超过插件写入上限的日志保留；磁盘日志不能授权删除后来新增的用户文件；
- 单份删除不影响另一份申报或共享缓存；全局缓存必须单独确认；
- 旧共享缓存预检不落盘，复制失败不触发付费请求，模型变化不会误用旧缓存。

界面夹具验证：确认前无删除、确认后进入阅读态拒绝、忙碌保护、失败后释放忙碌标志、重复确认不重复执行，以及清理不触碰请求计数或设置持久化。

## 独立审查与处理

两轮只读对抗审查发现并修复了以下真实问题，新增对应回归用例：

1. 登记图片被替换后仍可能按路径删除 → 增加登记哈希核对。
2. source 删除后目录失败无法重试 → 将收尾记录移到单份目录之外，并只允许空目录收尾。
3. 日志部分写入可能堵塞重试 → 临时写入、原子提交及有界的临时日志重试。
4. 合法 JSON 中的畸形 assets 导致异常 → 校验键、路径、哈希与图片清单一致性。
5. 未知空目录被当作垃圾 → 目录同样应用白名单。
6. 扫描期间新增目录触发 nil 索引 → 返回“检查中变化，请重试”，不使用混合时间点的数据。

复核确认前五项关闭，最后一项由父会话修复并通过新增回归。本记录不是“不存在其他缺陷”的保证。

- 扫描限定配置的工作目录与 SEC 书库，最多 10,000 项、16 层。缺根、不可读、链接或超过上限时停止，不把它们视为“全删了”。
- 单个待清理文件哈希读取上限 256 MiB；清理记录上限 1 MiB。空间按文件逻辑长度估算，不等于实际文件系统分配块数。

- 不猜测所有历史合集名称或未知素材批次的归属；无法证明时保留并说明，而不是全目录强删。
- 删除本地侧车不等于清空全局历史/收藏；KOReader 可能仍保留缺失书目的历史项。
